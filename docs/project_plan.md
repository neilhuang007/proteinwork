# Project plan for protein sequence sampling with Extropic

Updated 21 October 2026.

## The project in plain language

We want to generate candidate protein sequences from an existing trained protein model using Extropic's THRML tools. The biology lead defines the protein task, reference sequence and allowed amino acid choices. Neil connects those inputs to a sampler, checks its accuracy, and investigates how to run the computation efficiently.

A trained model gives numerical scores to individual amino acids and combinations of amino acids at different positions. Those scores define probabilities for complete sequences. Sampling means generating sequences according to those probabilities. Some sequences appear more often than others, and a sequence can appear more than once.

Our research question is: can an encoded sampling method using Extropic's tools, together with a simple method selection rule, reach the required sampling accuracy sooner than a direct sampler?

The central result will be a reproducible comparison of the methods on the same protein model and restrictions. We will measure total runtime, sampling accuracy and the biological properties that the available evidence lets us assess.

## How Extropic fits into the project

THRML is Extropic's software library for building and sampling probabilistic models. We use it to develop and test the sampling computation. The existing repository pilot runs a small THRML model on a CPU. The next implementation connects the verified components to the protein model.

The planned encoded method represents amino acid choices using binary variables, which have two possible values. It generates proposed changes using that representation and applies a correction against the original protein model. The correction is part of maintaining the intended sequence probabilities.

Neil will investigate which operations and independent sampling runs can execute together. Hardware planning will identify the actual Extropic device, runtime, supported model representation and access method. Physical device execution becomes a separate implementation milestone once those details are available. Each result will identify where it ran.

Extropic's [THRML documentation on GitHub](https://github.com/extropic-ai/thrml) describes its software sampling tools and backend interface. The local dependency versions and pilot records remain the starting point for implementation.

## What the program receives

Each sampling case will contain:

1. The trained protein model and its exact source version.
2. The reference protein, modeled region and map between biological residue numbers and computer positions.
3. The exact allowed amino acid letters at each position, including fixed residues and gap handling.
4. The model temperature, a numerical setting controlling how strongly score differences affect probabilities.
5. Sampling settings: the method, starting sequences, random seeds, initialization period, requested observations and run budget.
6. The biological summaries and sequence export requirements.

The first production interface supports fixed residues and allowed sets at individual positions. The biology lead also investigates relationships between positions. The team classifies each proposed relationship as an existing model interaction, an interpretation or ranking criterion, or an additional required constraint needing a defined implementation and correctness check.

An existing sequence alignment supplies biological context. The trained model supplies the numerical scoring terms used by the sampler. Both inputs have distinct roles in the handoff.

## What the program returns

Each run will produce:

* A record of complete sequence states, including repeated states after rejected proposals.
* The original model score for each recorded state, acceptance information and the settings that produced it.
* Sampling summaries such as residue frequencies, selected residue pair frequencies, reference distance and uncertainty.
* A timing breakdown covering input preparation, encoding, compilation, initialization, sampling, correction, transfers and reporting.
* A separately exported candidate library with its selection procedure and links to the source run.

The raw sampling record preserves the frequencies generated by the method. A library containing distinct sequences is a separate output, because removing duplicates changes those frequencies.

## A small example of the intended behavior

Consider four positions with choices A or V, then C, then D or G, then E. The possible sequences are ACDE, ACGE, VCDE and VCGE.

For this teaching example, suppose the model assigns them probabilities of 40%, 30%, 10% and 20%, respectively. A well explored sampling run should approach those proportions. In 1,000 observations from the target distribution, the expected counts are 400, 300, 100 and 200, with variation between runs.

Listing all four sequences helps us calculate the exact answer for this small test. The production task is to draw representative samples from much larger models. Its success criterion is accuracy of the sampling distribution and useful runtime.

Their deliverables are the protein choice, engineering goal, reference mapping review, allowed residue choices, biological reasoning, experimental evidence and requested summaries. They explain how a complete set of choices becomes a candidate sequence and how to assess that candidate. The [biology guide](biology_lead_guide.md) gives the detailed assignment.

Neil owns the software and computational comparison. His deliverables are the input loader, direct sampler, encoded representation, proposal correction, THRML integration, execution strategy, correctness checks, run records and performance measurements. The [computer lead guide](computer_lead_guide.md) explains the work step by step.

Both leads review one displayed input and output together, agree which biological question each case addresses, and check that the software uses the intended positions and residues. Adviser and specialist reviews resolve the benchmark decisions and the encoded sampling method.

## How we will establish that it works

### Check the representation and arithmetic

Verify that every encoded state used as a protein candidate decodes to the intended amino acids. Confirm position numbering, gap treatment, allowed residues and the model score using independent calculations. Preserve the original model's excluded choices exactly.

### Check the sampler on small models

Use small cases whose possible sequences and exact probabilities can be calculated directly. Check the update probabilities mathematically, including the probability of remaining in the same state after rejection. Compare observed sequence frequencies with the exact target and quantify the sampling uncertainty.

### Check the protein runs

Run four independently initialized chains, meaning four separate sampling histories, for each comparison condition. Compare residue frequencies, selected pairs, model scores and reference distances. Examine whether the runs agree and how much independent information their correlated observations contain.

For larger cases, use separately qualified long reference runs with quantified uncertainty. The existing [evaluation settings](../configs/evaluation.json) and [benchmark contract](week04/benchmark_contract.md) contain the proposed thresholds and budgets for review.

### Compare complete runtime at the same accuracy

Compare a direct sampler, a fixed corrected encoded method, and a simple planner that selects a verified method using development results. All methods use the same original model, restrictions, temperature and accuracy requirements. Include preparation and correction in the runtime.

The planner is a small decision rule for choosing a method and update schedule before a run. It will be developed using designated cases and kept fixed during final evaluation.

### Assess the biological question

Use the biology lead's criteria to interpret the candidate libraries. Record the measured sequences and conditions behind any experimental comparison. Identify which evidence informed the model or rules and which provides a separate evaluation. Report the measured coverage of the generated library alongside the biological findings.

## Our starting point

The repository contains preparation through Week 4: model reading exercises, small adabmDCA and THRML pilots, encoding investigations, a CM model proposal, a position map and draft comparison cases. The full project samplers and their protein integration are the next implementation work.

The current proposed family is chorismate mutase. The biology lead's recent alignment work uses Kunitz. The first joint biological decision is to confirm the family and compatible trained model, then record the choice in the shared inputs.

The saved CM proposal and numerical settings remain the current technical reference until a documented change replaces them. Each change to a model, restriction, temperature or evaluation criterion receives a version and a reason so that comparisons remain reproducible.

## Proposed schedule

We retain the original 18 project weeks and planned budget of 182 hours per person. Weeks 1 through 4 account for 36 planned hours per person. The remaining stages account for 146 planned hours per person. These are project weeks; calendar deadlines will be attached when agreed.

### Weeks 5 through 7: Connect the biological inputs to a direct sampler

Neil builds the production loader, validates allowed residues, verifies scores and implements a direct sampler. A direct sampler works with amino acid choices themselves. Connect it to run records, diagnostics and candidate export. Review the Extropic software interface and record the hardware information needed for later device work.

The biology lead resolves the family choice, explains the biological task, reviews the reference positions and supplies the initial residue requirements and output expectations.

This stage is complete when tiny model probabilities are verified and a small protein case produces a traceable sampling run that both leads can interpret. Planned time: 30 hours per person.

### Weeks 8 through 10: Build and verify the Extropic sampling path

Neil defines the binary representation, the actual proposal schedule and the correction that preserves the original target. Review that method with the sampling specialist, implement it using the selected THRML components, and test invalid proposals, rejections and complete state recording. Connect the verified method to the same protein inputs as the direct sampler.

The biology lead reviews decoded sequences and confirms that the residue choices, numbering and export meaning remain consistent across methods.

This stage is complete when both methods pass the agreed small model checks and run on the same protein case. Planned time: 36 hours per person.

### Weeks 11 through 12: Measure costs and develop the planner

Neil measures preparation, compilation, sampling, correction and reporting costs. Investigate batches of independent chains and permitted parallel updates. Compare the fixed methods on development cases, then implement a simple rule for choosing the method and schedule.

The biology lead supplies useful workload cases, desired library sizes and a practical interpretation of time saved.

This stage is complete when development measurements explain the planner's choices and identify the relevant execution costs. Planned time: 20 hours per person.

### Week 13: Freeze the final comparison

Both leads settle the evaluation cases, accuracy criteria, biological summaries, export selections and reporting procedure. Record the software versions, model versions and execution environment. Resolve peer feedback and check unusual inputs.

This stage is complete when the final comparison can be run from a fixed written procedure. Planned time: 10 hours per person.

### Weeks 14 through 15: Run and interpret the comparison

Neil compares direct sampling, fixed encoded sampling and planner selected execution using four chains and equal development budgets. Record failures to reach the accuracy target within the run budget, along with completed runs. Investigate discrepancies and run the planned checks of which components contribute to performance.

The biology lead interprets residue patterns, diversity, reference distance and eligible experimental matches in the candidate libraries.

This stage is complete when the results connect runtime and sampling quality to the biological task. Planned time: 24 hours per person.

### Week 16: Reproduce the workflow

Another team member follows the recorded setup and run instructions. Neil resolves software and reproducibility problems. The biology lead checks that the sequence descriptions, input rules and outputs are understandable.

This stage is complete when the reproduction and any fixes are documented. Planned time: 10 hours per person.

### Weeks 17 through 18: Finish the report and release

Use the remaining time for essential corrections, the final analysis, report, presentation and demonstration. Package the code, input versions, raw records, summaries and instructions together.

This stage is complete when another reader can understand the biological question, reproduce the computational comparison and trace the reported findings to saved results. Planned time: 16 hours per person.
