Protein Sequence Sampling Project
Week 4 Report

This week, I focused on bringing my earlier research and coding exercises together into a clear plan for testing the protein sequence sampling project. According to the working project schedule, my main tasks were to update the project plan, prepare a concrete benchmark, and organize the materials for review with both project leads and the adviser. I completed the technical preparation, including the model's source information, a map of its sequence positions, rules for allowed amino acids, and proposed evaluation criteria. This completes the technical portion of the Week 4 milestone, although the scheduled review is still outstanding. I therefore have a package ready for discussion, with final agreement on the benchmark remaining an unfinished task.

One of the most useful outcomes was resolving a question that had followed me since the initial model-reading exercise. The chorismate mutase model contains 362 negative-infinity entries, which represent amino-acid choices that the model assigns zero probability. Understanding their meaning helped me turn an unfamiliar feature of the data into a clear implementation requirement: the code must preserve these exclusions when loading the model and generating sequences. This work reinforced how closely the software's behavior depends on interpreting the original model correctly.

I also checked how the model's 96 aligned positions connect to the biological reference sequence. Of those positions, 89 correspond to amino acids and seven are alignment gaps. Making that distinction explicit will help me apply restrictions to the intended positions. During this process, I found that the reference sequence contains two choices that the model excludes. I addressed this by keeping the reference for position numbering and documenting a separate computational sequence that satisfies the model's rules. Working through this issue helped me understand why a useful biological reference does not automatically provide a valid starting point for sampling.

On the coding side, the benchmark validation work produced four restriction cases, each containing valid sequences. Two cases are small enough to check every possible state, giving me exact results to compare against when I implement the samplers. The recorded validation run passed all 10 benchmark tests, and two numerical approaches agreed on a reference sequence's energy. These results give me a stronger foundation for development. I also separated the development and evaluation cases so that later tuning decisions can be assessed on inputs reserved for evaluation.

The main implementation obstacle is that the installed adabmDCA loader rejects the model's non-finite entries. To address this, I made explicit handling of excluded choices a requirement for the upcoming loader. I retained the overall milestone order and clarified the evaluation plan by proposing equal runtime budgets and common accuracy targets. I also excluded experimental labels already used in developing the model from independent biological evaluation. Formal adviser feedback remains pending; after the review, I will record any requested changes and update the benchmark settings and affected checks.

Next week, I plan to follow up on the outstanding review and begin the Week 5 implementation tasks. These include building the model loader, checking positional restrictions and score calculations, and completing the planned JAX array and compilation exercises. My priority is to make the model's rules reliable in code before moving into sampling comparisons. This week's work has made the next stage more concrete: I now have defined inputs, reference calculations, and specific problems to resolve as I build the workflow.
